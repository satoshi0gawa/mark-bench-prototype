01 / OVERVIEW

制作概要

BLOGDEMOは、注目記事、人気記事、新着記事、カテゴリ、検索、記事詳細を横断して閲覧できるマガジン風のデモサイトです。
公開環境では「FICTIONALMEDIA」として、架空の記事、人物、団体、店舗情報を用いて表示と運用を確認できます。

Figmaデザインを静的なページとして組み立て、その構造をWordPressのテンプレートと投稿データに対応させた構成です。
記事や画像を追加・変更しながら、デザインと更新方法の関係を学ぶ制作物として運用しています。

掲載画像にはUnsplashなどの素材を使用しています。

02 / REQUIREMENTS

目的と要件

制作目的は、静的に完成した複数ページのデザインを、投稿や分類を管理画面から更新できるWordPressテーマへ展開することです。
記事数の変化や画像の未設定も想定し、更新時の扱いやすさを目指しています。
次の項目を、制作・改善時の要件として整理しています。

  1. 注目記事、人気記事、新着記事の役割を分け、同じ記事の重複表示を抑える。
  2. 投稿、カテゴリ、タグ、検索結果、固定ページをWordPressの標準データで出力する。
  3. PC用とSmartphone用の画像を使い分け、未設定時はアイキャッチやテーマ画像へフォールバックする。
  4. グローバル、補助、フッター、検索キーワードの各ナビゲーションを管理画面から変更可能にする。
  5. ABOUT、CONTACT、PRIVACY POLICYを専用テンプレートとして整備する。
  6. 情報、アクセス、記事カルーセルを再利用可能なカスタムブロックとして提供する。
  7. メニュー、外部リンク確認、表示アニメーションをキーボードと動きを抑える設定へ対応させる。
  8. 制作確認用デモは検索対象外とし、Basic認証のサーバー設定をテーマのソースコードへ含めない。

学習面では、静的HTMLのテーマ化、セキュリティ設定、表示速度の改善を中心に取り組んでいます。
追加機能とWordPress標準機能の役割を知り、管理画面の設定が表示へどう反映されるかを理解していくことも目的です。

03 / SCOPE

担当範囲

企画やFigmaデザイン、目指す表示・操作の整理に取り組み、コードの作成・修正、PHPやJavaScriptの実装方針、テーマの機能追加にはCodexを利用しています。
画面を見て気づいた点を伝え、修正結果を確認する形で制作を進めています。
以下に、制作で扱っている工程と進め方をまとめます。

  1. 企画・情報設計：載せたい記事や読者導線を整理し、一覧・詳細・固定ページの役割を検討。
  2. デザイン：Figmaでレイアウトやブランドトーンをまとめ、実装画面と見比べながら調整。
  3. 静的実装：デザインをもとにHTML・CSS・JavaScriptの実装を依頼し、表示や操作の要望を伝えて調整。
  4. テーマ化：静的HTMLのテンプレート分割とPHPへの置き換えを依頼し、各ページとの対応を学習。
  5. CMS設計：投稿・分類・メニュー・画像など、管理画面から変更したい項目を整理し、更新方法を学習。
  6. ブロック実装：記事内で使いたい情報・アクセス・カルーセルの用途を伝え、動的Gutenbergブロックの実装を依頼。
  7. 検証・改善：表示・操作で気づいた問題を共有し、修正と再確認を進める。
    検証の観点は「検証と公開」に整理。
LEARNING FOCUS

HTML・CSSの知識を土台に、JavaScriptやPHP、WordPressの仕組みを学んでいる段階です。
今後はテンプレートの役割、設定変更の影響範囲、セキュリティ設定の意味、表示速度の測定と改善を、自分で説明できる範囲から広げていきたいと考えています。
画像素材そのものの撮影・制作は担当範囲外です。

04 / STRUCTURE

サイト・ページ構成

一覧で記事を発見し、カテゴリや検索で絞り込み、記事詳細と固定ページへ移動できる構成です。

BLOGDEMOのページ構成
ページ・領域 役割
Front Page 注目記事、人気記事、新着記事、検索、サイドバーをまとめた入口
Category / Tag Archive 分類ごとの記事一覧と代表記事の提示
Search Results 検索語に一致した記事一覧と0件時の案内
Single タイトル、記事情報、本文、タグ、Recommendを表示する記事詳細
ABOUT サイトコンセプト、編集方針、運営情報
CONTACT 問い合わせ目的とフォームUI
PRIVACY POLICY 個人情報、アクセス解析、免責事項の案内
Header / Drawer / Footer カテゴリ、検索、固定ページ、SNSへの共通導線

Front Pageでは、featuredタグの記事を注目枠、popularタグの記事を人気枠へ表示し、それらを新着一覧から除外する構成です。
同じ記事の重複を抑えながら、それぞれの枠で異なる記事を見せる仕組みになっています。

05 / ARCHITECTURE

技術構成とファイル設計

現在のテーマは、WordPressのテンプレート階層に沿ったページ別ファイルと、画像取得などをまとめた共通処理に分かれています。
以下は、テーマ内の主要ファイルと役割を整理したものです。

BLOGDEMOの技術構成
技術・ファイル 主な役割
front-page.php 注目、人気、新着を個別のWP_Queryで取得し、サイドバーと検索を配置
archive.php / search.php カテゴリ・タグ・検索結果の一覧表示
single.php 記事見出し、本文、タグ、Recommendの出力
page-*.php ABOUT、CONTACT、PRIVACY POLICYの固定ページ固有構成
header.php / footer.php 共通ナビゲーション、ドロワー、外部リンク確認モーダル
functions.php テーマ機能、メニュー、画像サイズ、SEO説明文、ACF、管理画面設定、ブロック登録
inc/template-functions.php 画像、抜粋、記事情報、フォールバック、メニュー出力の共通処理
blocks/ 情報、アクセス、記事カルーセルの動的Gutenbergブロック
js/main.js メニュー、表示アニメーション、外部リンク確認モーダルの状態管理

テーマでは post-thumbnails、HTML5、レスポンシブ埋め込みなどを有効化し、カード用1000×563pxとSmartphone用1000×1250pxの画像サイズを追加しています。メニューはGlobal、Utility、Footer、Sidebar Search Keywordsの4か所を登録しています。

06 / IMPLEMENTATION

主要な実装ポイント

記事の取得、画像の選択、管理画面からの更新、操作状態の管理について、現在のコードがどのように動くかをまとめます。

記事の役割をタグと取得条件で管理する

Front Pageでは、featuredタグから注目記事を1件、popularタグから人気記事を4件取得します。
取得済みIDをまとめ、新着記事の post__not_in へ渡すことで、注目・人気・新着の重複表示を抑える仕組みです。

指定タグの記事が存在しない場合も、ダミー見出しやテーマ画像へフォールバックし、初期状態でレイアウト全体が崩れないようにしています。

画像の用途と未設定時の挙動をまとめる

記事画像は、メイン表示、カード表示、Smartphone表示で必要な比率が異なります。
アイキャッチを基準にしながら、ACFが有効な場合は blogdemo_main_image_sp と blogdemo_card_image を追加指定できる構成です。

ACFが無効、追加画像が未設定、アイキャッチがない場合は、共通関数が段階的に代替画像を選びます。
テンプレート側へ同じ条件分岐を繰り返さず、画像の変更と例外対応を追いやすくしています。

更新頻度の高い要素を管理画面へ移す

サイドバーバナーはテーマ設定画面から画像、リンクURL、代替テキスト、補足文を登録する構成です。
固定ページ用のSEO説明文、検索結果の表示件数、フッターコピーライトも管理画面で変更する項目として用意されています。

記事本文では、店舗情報、アクセス情報、記事カルーセルを動的Gutenbergブロックとして登録しています。
各ブロックは block.json で属性を定義し、PHPの render.php で出力します。

操作状態をHTML属性と同期する

モバイルメニューは開閉状態をBodyクラス、aria-expanded、aria-hiddenへ反映し、閉じるボタンとEscapeキーに対応しています。
外部リンク確認モーダルは遷移先URLと補足文を動的に設定し、開く前の要素へフォーカスを戻します。

ページ導入と記事カードの表示には IntersectionObserver を使用し、非対応環境では即時表示します。
prefers-reduced-motion: reduce の場合は動きを省略し、内容と操作が失われないようにしています。

07 / QUALITY

レスポンシブとアクセシビリティ

最大1200pxの共通コンテナを基準に、1024px、768px、767px、499px付近で、一覧とサイドバー、画像比率、ナビゲーション、余白を段階的に切り替えています。

BLOGDEMOのレスポンシブ対応
条件 表示の切り替え
PC 注目記事と人気記事、新着一覧とサイドバーを並べ、情報量を一覧できる構成
Tablet 列幅と余白を調整し、カードとサイドバーの比率を維持
Smartphone メニューをドロワー化し、検索ワード、記事カード、固定ページを1列中心へ再配置
767px以下 ACFのSmartphone用記事画像を優先し、未設定時はアイキャッチを継続使用
499px以下 見出し、カード、固定ページの余白を小さい画面向けに調整

各記事群とナビゲーションには見出しまたは aria-label を設定し、検索入力にはラベルを関連付けています。
ドロワーとモーダルはEscapeキーで閉じられ、モーダル終了後は操作元へフォーカスを戻します。
外部リンクは新しいタブで開く場合に rel="noopener noreferrer" を併用しています。

アニメーションを情報の理解に必須とせず、動きを抑える設定でも内容を読めることを目指しています。
レイアウトや操作の実装仕様と、端末・操作条件ごとに確認できた結果は分けて記録する方針です。

08 / CHALLENGES

課題と解決

静的な画面をCMSで更新できる形へ変える際の課題と、現在採用している対応を整理します。

  1. 01課題

    静的版では画像と記事情報が各HTMLへ固定されています。
    WordPressで更新できる形へ移すには、記事数、分類、画像設定の変化を表示へ反映する処理が必要です。

  2. 02原因

    CMSでは、完成画面だけでなく未入力や件数の変化も扱います。
    画像を選ぶ処理が各テンプレートへ散らばると、設定漏れへの対応や代替画像の選び方に違いが生まれやすくなります。

  3. 03解決

    現在のテーマは、画像取得、抜粋、記事情報、メニュー出力を共通関数へまとめる構成です。
    画像は「用途別ACF画像 → アイキャッチ → テーマ内ダミー画像」の順で選び、記事取得条件と除外IDはFront Pageにまとめています。

  4. 04結果

    代替画像の選択などを共通処理で扱うため、変更箇所をまとめやすい構成になっています。
    管理画面で登録する内容とテーマが補完する内容を分けて把握することが、運用時の学習ポイントです。

09 / REVIEW & DELIVERY

検証と公開

検証では、コードや設定のチェックと、管理画面・ブラウザでの操作確認を分けて扱います。
以下は、変更時に確認する観点を整理したものです。

管理画面・ブラウザでの確認項目

  1. Front Page、カテゴリ、タグ、検索、記事詳細、固定ページのテンプレート切り替え。
  2. 注目、人気、新着の記事取得条件と重複除外。
  3. 投稿0件、タグ未設定、アイキャッチ未設定、ACF無効時のフォールバック。
  4. PC / Tablet / Smartphoneの配置、画像切り替え、ページ全体の横スクロール。
  5. ドロワーと外部リンク確認モーダルの状態、Escapeキー、フォーカス復帰。
  6. 検索フォーム、カテゴリ、タグ、固定ページへのキーボード移動。
  7. prefers-reduced-motionとIntersection Observer非対応時の表示。
  8. カスタムブロックの編集値、動的出力、画像リンク、余白設定。

コード・公開設定の確認項目

PHPの構文、ブラウザのコンソールエラー、画像やスクリプトの参照先、公開URLのHTTP応答などを確認する項目としています。
ツールで調べられる結果と、実際の表示・操作の結果を照らし合わせ、変更箇所・確認条件・結果を記録していく方針です。

制作確認用のデモはBasic認証で保護する運用です。
WordPress側は noindex,nofollow とし、テーマ内のSEO説明文をページ種別に応じて出力しています。
Basic認証のサーバー設定はテーマや公開リポジトリへ含めず、閲覧案内用の共通パスワードのみ本記事に掲載しています。

検索公開へ切り替える場合は、認証解除、index設定、canonical、OGP、リンク切れを改めて確認します。

セキュリティ設定は、認証や検索対象外の指定など、各設定の役割を理解するところから学んでいます。
表示速度についても、測定する条件と指標、変更前後の結果を残しながら改善を進めることを今後の課題としています。
