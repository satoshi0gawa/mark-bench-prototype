01 / OVERVIEW

制作概要

CITY RUN TOKYO 2027は、東京の街並みや文化を楽しみながら走る架空イベントの大会情報・参加促進サイトです。
ページは HERO → RACE → ABOUT → COURSE → EVENT → ENTRY の順に構成し、イベントの第一印象から種目選択、体験内容、エントリーまでを1ページで追えるようにしました。

基本となるセクション数とレイアウトは提供カンプを継承し、企業紹介向けだったコピー、画像、配色、書体、ロゴ、CTA、メタ情報をイベント向けに刷新しています。
3枚のヒーロー画像、開催日までのカウントダウン、ファーストビュー通過後の追従ヘッダー、Tablet・Smartphone用ドロワー、ページ内移動、スクロール表示を実装しました。

02 / REQUIREMENTS

目的と要件

課題の目的は、既存LPの構造を別業種へ展開するとき、レイアウトを大きく作り直さなくても、コンテンツ設計とブランド表現の変更によって目的の異なるサイトへ転換できるかを検証することでした。

起点には、Shogo（しょーごログ運営）さんの教材「【即戦力編】Photoshopデザインカンプからのコーディング練習」を使用しています。
元のPhotoshopカンプ、基本レイアウト、当初の企業サイトとしての要件は教材提供であり、そのデザイン制作は担当していません。

  1. 既存のHTML大枠、セクション数、カード数、レスポンシブ構造を活用する。
  2. 企業情報を、大会情報、コース、体験、参加導線へ読み替える。
  3. ブランド、コピー、写真、色、書体、ロゴ、CTAを一つの方針から再定義する。
  4. PCだけでなく、TabletとSmartphoneで情報の優先順位が崩れないようにする。
  5. キーボード操作や動きを抑える設定でも、情報と操作を失わないようにする。
  6. 制作確認用デモは検索対象外とし、Basic認証のサーバー設定をHTML、JavaScript、Git管理対象へ含めない。

刷新後のテーマは「都市体験 × ランニング × カルチャー」です。
Off White、Black、Limeを基調とし、英字にはSpace Grotesk、日本語にはNoto Sans JPを使用しました。
元の構造を残すこと自体を目的にせず、その構造が新しい利用目的に適合するかを各セクションで判断しています。

03 / SCOPE

担当範囲

担当したのは、CITY RUN版の企画から実装・検証までです。

  1. 企画・情報設計：架空イベントのコンセプト、セクションの役割、コピー、CTAの優先順位を定義。
  2. ビジュアルディレクション：配色、書体、画像方針、オリジナルロゴ、斜面モチーフを設計。
  3. マークアップ：見出し、ランドマーク、リスト、time、代替テキスト、アンカーIDを再構成。
  4. スタイリング：既存レイアウトを活かしながら、ブランド表現と画面幅別レイアウトを実装。
  5. インタラクション：ローディング、追従ヘッダー、ドロワー、ページ内移動、表示監視、カウントダウンを実装。
  6. レビュー：レスポンシブ、キーボード操作、動きの代替、メタ情報、アセット参照を確認。
SCOPE BOUNDARY

提供カンプ由来の基本構造と、CITY RUN向けに新規定義した企画・ブランド・コンテンツ・実装調整を明示的に分けています。

04 / STRUCTURE

サイト・ページ構成

元の企業LPにあった情報の枠を、次のようにイベント参加の流れへ対応付けました。

元の企業LPとCITY RUN版の構成対応
元の役割 CITY RUN版 新しい役割
TOP HERO / NEWS ブランドの第一印象と最新情報
SERVICES RACE 種目・大会情報への導線
ABOUT ABOUT 都市型イベントの思想
WORKS COURSE CITY HALF / CITY 10Kの紹介
RECRUIT EVENT EXPO、飲食、音楽などの体験紹介
CONTACT ENTRY 参加エントリーと大会概要へのCTA

セクション名だけを交換すると、企業紹介の文脈とCTAの優先順位が残ります。
そのため、見出し、本文、写真の意味、カード同士の関係、リンク先をまとめて見直しました。
実績カードだった2カラムは2種類のコース紹介へ、採用カードだった3カラムは会場体験の紹介へ転換しています。

ナビゲーションは TOP / RACE / ABOUT / COURSE / EVENT / ENTRY に統一しました。
未確定の外部遷移はデモ用の空リンクとし、ヘッダー、ドロワー、フッターのページ内リンクだけを実在するセクションIDへ接続しています。

05 / ARCHITECTURE

技術構成とファイル設計

HTMLは情報構造、CSSはレイアウトと視覚表現、JavaScriptは状態変化と操作を担当するよう責務を分けました。

使用技術と主な役割
技術 主な役割
HTML ランドマーク、見出し階層、リスト、time、picture、ARIAによる文書構造
CSS Grid、Flexbox、clip-path、gradient、疑似要素、キーフレームによるレイアウトと演出
JavaScript 追従ヘッダー、ドロワー、ページ内移動、表示監視、ローディング、カウントダウン
Photoshop 提供カンプの計測、刷新後のPC・SPデザインと画像構成の確認
WebP / SVG 画面幅別写真の配信、ロゴと操作アイコンの解像度非依存表示

ページ固有の構成は index.html、スタイルはSCSSをlayout・component・page・utilityへ分け、生成した css/style.css を読み込みます。JavaScriptは js/main.js に機能単位の初期化関数を置き、DOMContentLoaded 後に共通初期化しています。

外部UIライブラリは使用せず、標準DOM APIと IntersectionObserver を中心に実装しました。
装飾の斜面、パネル、ボタン背景は、文字量の変更や高解像度表示へ追従できるよう、写真とロゴを除いて可能な限りCSSで構成しています。

06 / IMPLEMENTATION

主要な実装ポイント

ブランドと情報設計を同時に置き換える

色と文言だけを変更すると、情報の順番や行動導線に企業サイトの意味が残ります。
各セクションの役割を先に定義し、その後にコピー、写真、ロゴ、色、書体、CTAをそろえることで、カード数を増減させず、イベントを知って参加を検討する流れへ再構成しました。

HEROと追従ヘッダーを一つの状態として扱う

HEROでは3枚のWebPを18秒周期でクロスフェードし、緩やかな拡大を加えています。
ファーストビュー下端が画面上端を通過すると、白背景・黒文字の追従ヘッダーへ切り替わります。
境界判定には IntersectionObserver を使い、非対応環境ではscrollイベントへフォールバックします。

ドロワーの見た目と操作状態を同期する

1024px以下では全画面ドロワーへ切り替えます。
開閉時に aria-expanded、aria-label、aria-hidden、inert を更新し、背景スクロールを停止します。開いた直後は先頭リンクへフォーカスし、Escapeで閉じた場合は開閉ボタンへ戻します。

開催日と読み上げ情報を同じ値から生成する

カウントダウンは2027年10月24日9時を基準に、日・時・分・秒を1秒ごとに更新します。
視覚表示は支援技術から重複して読まれないようにし、親要素の aria-label を同じ計算結果から更新しています。
期限到達後は負の値を出さず、0で停止します。

動作しない環境でも本文を残す

スクロール表示は、JavaScriptの初期化に成功した場合だけ非表示状態を有効にします。
表示後は監視を解除し、IntersectionObserver 非対応、処理例外、prefers-reduced-motion: reduce の環境では対象を即時表示します。演出を追加しても、本文を読む条件にはしない設計です。

07 / QUALITY

レスポンシブとアクセシビリティ

PC、Tablet、Smartphoneを単純な縮小関係にせず、利用できる幅と操作方法に応じて構成を切り替えました。

画面幅ごとのレイアウト切り替え
条件 表示の切り替え
1025px以上 大きなHEROコピー、横並びナビゲーション、写真と斜面を活かした広い構図
769〜1024px コンパクトヘッダーとドロワー、セクションごとの余白・画像焦点・斜面長を調整
768px以下 カードとCTAを縦方向へ再配置し、タッチ操作を優先
480px以下 長い日本語見出し、NEWS本文、HEROコピーのはみ出しを抑制

画像はHERO用に768 / 1366 / 1920 / 2400px、主要コンテンツ用に1x / 2x候補を用意し、picture とWebPで表示幅に合う画像を選択します。
確認基準は375 / 768 / 1024 / 1366pxとし、ページ全体の横スクロール、画像の焦点、メニュー、アンカー停止位置を確認しました。

セクションと見出しを aria-labelledby で関連付け、ローディングに role="status"、カウントダウンに role="timer" を設定しました。
操作要素には :focus-visible を用意し、Lime背景には黒文字、ENTRYの写真背景には暗色レイヤーを重ねて可読性を確保しています。
動きを抑える設定では、HEROを1枚目の静止表示にし、移動・拡大・スムーススクロールを抑えます。

08 / CHALLENGES

課題と解決

  1. 01課題

    企業LPの構造をそのまま使うと、会社紹介の文脈や青系の重厚な印象が残り、参加を促すイベントサイトとして意味がつながりませんでした。

  2. 02原因

    セクション名だけを置き換えても、情報の役割、CTAの優先順位、写真の方向性、書体と配色のトーンが元の業種を示し続けます。
    また、表示演出とホバーが同じtransformを変更すると動きが競合します。

  3. 03解決

    各セクションをRACE / COURSE / EVENT / ENTRYへ対応付け、ブランド方針からコピー、写真、色、フォント、ロゴ、アンカー、メタ情報を再定義しました。
    ホバー対象はスクロール表示用クラスから分離しています。

  4. 04結果

    基本レイアウトとカード数を維持しながら、大会の第一印象からエントリーまで意味が連続するサイトへ転換できました。
    構造と視覚表現、表示演出と操作状態を分離し、再利用性を保った別ブランド展開を実現しています。

09 / REVIEW & DELIVERY

検証と公開

実装後は、次の観点で確認しました。

  1. ランドマーク、見出し階層、time、画像の代替テキスト。
  2. 旧企業名、旧セクション名、旧アンカーの残存有無。
  3. HERO、カード、斜面、CTA、画像焦点の表示。
  4. PC / Tablet / Smartphoneの再配置と横スクロール。
  5. ローディング、追従ヘッダー、ドロワー、アンカー移動、カウントダウン。
  6. Tab、Enter、Escape、フォーカス表示と復帰。
  7. 通常表示と prefers-reduced-motion の代替状態。
  8. JavaScriptエラーと未解決アセットの有無。

制作確認用デモには noindex,nofollow を設定しています。
Basic認証のサーバー設定はサーバー側で管理し、閲覧案内用の共通認証情報のみ本記事に掲載しています。
公開先では、未認証、正しい認証情報、誤った認証情報の3条件で動作を確認する運用です。

デモ本体のcanonical、og:url、OGP画像、Twitter Cardは公開先の絶対URLへそろえます。
検索公開するサイトへ切り替える場合に限り、公開方針を確認したうえで noindex を解除します。
