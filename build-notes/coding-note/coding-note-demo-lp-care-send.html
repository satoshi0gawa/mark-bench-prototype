01 / OVERVIEW

制作概要

CareSendは、サービスの特徴、導入実績、事例、料金、FAQを伝え、資料請求へつなげる介護人材派遣サービスの架空LPです。
提供されたPC・Smartphone用Figmaカンプを基準に、中間幅を補完しながらレスポンシブ実装しました。

ページ内には、企業ロゴの自動スクロール、導入事例の手動スライダー、ドロワーメニュー、FAQアコーディオン、資料請求フォームを実装しています。
フォームは操作確認用のデモで、入力内容の保存・外部送信・資料の配布は行いません。

02 / REQUIREMENTS

目的と要件

本制作は、Shogo（しょーごログ運営）さんの教材「【中級】デザインカンプからのコーディング実践演習【JavaScript導入】」を使用した学習課題です。
レイアウトとビジュアルは教材から提供されたFigmaカンプを参照しており、デザイン制作は担当していません。

課題の目的は、カンプの数値を写すだけでなく、セクションの意味と操作の役割を読み取り、保守できるHTML・SCSS・JavaScriptへ変換することでした。

  1. ランドマークと見出し階層を整え、長いLPの情報構造を追えるようにする。
  2. PC・Smartphoneのカンプ間を補完し、Tabletを含む中間幅でも破綻させない。
  3. 自動で流す情報と利用者が読む情報で、スライダーの操作方法を分ける。
  4. FAQとフォームを標準HTMLの機能を基礎に実装する。
  5. キーボード操作、フォーカス表示、動きを抑える設定へ対応する。
  6. フォームが送信されないことを画面上で明示する。
  7. 制作確認用デモは検索対象外とし、Basic認証のサーバー設定をソースコードへ含めない。

デザイン再現と同時に、入力、開閉、移動といった状態変化が見た目だけでなく、HTML属性や支援技術向けの情報にも反映されることを重視しました。

03 / SCOPE

担当範囲

担当範囲はフロントエンド実装と実装後の検証です。

  1. マークアップ：Figmaからセクションの関係を読み取り、HTMLのランドマーク、見出し、リスト、フォームへ変換。
  2. スタイリング：SCSSをfoundation、layout、component、page、utilityへ分割し、生成CSSへ反映。
  3. レスポンシブ：PC・Smartphoneのカンプを基準に、Tabletと境界幅のレイアウトを補完。
  4. インタラクション：ドロワー、2種類のスライダー、FAQ、フォーム、スクロール表示を実装。
  5. デバッグ：表示件数、可変高、ボタン状態、フォーカス、画面幅ごとの崩れを修正。
  6. セルフレビュー：構造、表示、操作、キーボード、コンソールエラーを確認。
SCOPE BOUNDARY

提供されたデザインと、自分が担当したコーディング・動作設計・検証の範囲を分けて記載しています。

06 / IMPLEMENTATION

主要な実装ポイント

情報の性質に合わせて2種類のスライダーを分ける

導入企業ロゴは、採用実績の広がりを連続的に伝える情報です。
そのためSplideのAuto Scroll拡張を使用し、横方向へ自動で流す表示にしました。
一方、導入事例は文章を一件ずつ読む必要があるため、自動再生を使わず、矢印で操作するスライダーにしています。

事例スライダーはPCで2件ずつ、1024px以下で1件ずつ表示し、現在位置に応じて前後ボタンの disabled と aria-disabled を同期します。
同じライブラリを使いながら、用途ごとに移動量、操作方法、画面幅設定を分けました。

標準のdetailsを保ちながらFAQを可変高で動かす

FAQは details と summary を使用し、JavaScriptが動かない場合でも標準の開閉操作を残しました。
アニメーション時は回答の開始高と内容高を計測し、Web Animations APIで補間します。
完了後は高さを auto へ戻し、文章量が変わっても固定値へ依存しない構成にしています。

prefers-reduced-motion: reduce またはWeb Animations APIが利用できない環境では、アニメーションを行わず開閉状態を即時反映します。

送信しないフォームでも入力体験を検証する

フォームは各入力欄を label と関連付け、required、入力型、autocomplete を設定しました。送信時は preventDefault() で通信を止め、reportValidity() によるブラウザ標準の必須入力検証を利用します。

入力が有効な場合は送信ボタンを無効化し、送信されない旨を示す role="status" の完了メッセージへフォーカスを移します。
実データを扱わずに、入力から結果通知までの操作と読み上げ順を確認できるデモにしました。

メニューとスクロール表示を代替可能にする

ドロワーは開閉状態と aria-expanded、操作ラベル、背景スクロール抑止を同期し、リンク選択またはEscapeキーで閉じます。スクロール表示は各セクションが交差した時だけ開始し、表示後は監視を解除します。IntersectionObserver 非対応または動きを抑える設定では、内容を即時表示します。

07 / QUALITY

レスポンシブとアクセシビリティ

PCとSmartphoneのカンプ間を単純に縮小せず、情報量と操作方法に応じて段階的に調整しました。

CareSend LPのレスポンシブ対応
条件 表示の切り替え
PC HEROの説明とフォームを横並びにし、事例を2件ずつ比較表示
1200px以下 横並びナビゲーションをドロワーへ切り替え
1024px以下 HEROと資料請求の内容を縦方向へ再配置し、事例を1件表示へ変更
480px以下 余白、カード、フォーム内の2列入力をSmartphone向けに調整
375〜1200px 見出し、本文、料金数値を clamp() で補間

各セクションを見出しと関連付け、操作ボタンに :focus-visible を用意しています。
フォームはラベル、入力型、必須状態、オートコンプリートを設定し、結果通知にはライブリージョンを使用しました。
事例スライダーの矢印は現在位置に応じて無効状態を伝え、FAQは標準要素を基礎にしています。

自動スクロール、FAQ、セクション表示、ボタンのtransitionは prefers-reduced-motion を考慮します。
動きを止めても、情報の閲覧と操作ができる状態を維持します。

08 / CHALLENGES

課題と解決

  1. 01課題

    企業ロゴと導入事例はどちらも横方向へ並ぶ情報ですが、同じスライダー設定では速度と操作性が情報の読み方に合いませんでした。

  2. 02原因

    自動で流し続けるロゴ一覧と、内容を一件ずつ読む事例カードで、必要な移動量と操作方法が異なるためです。

  3. 03解決

    企業ロゴはAuto Scrollによる連続表示、導入事例は矢印による手動操作へ分離しました。
    事例はPCで2件、1024px以下で1件ずつ移動し、先頭と末尾では該当する矢印を無効化します。

  4. 04結果

    同じSplideを使用しながら情報の役割に合った速度と操作方法を設定し、実績の量と個別事例の内容をPCからSmartphoneまで追いやすい表示にできました。

09 / REVIEW & DELIVERY

検証と公開

実装後は次の観点で確認しました。

  1. ランドマーク、見出し階層、リスト、フォームラベルの関係。
  2. PC / Tablet / Smartphoneの配置とページ全体の横スクロール。
  3. ドロワーの開閉、リンク選択、Escapeキー、背景スクロール。
  4. 企業ロゴの自動表示と導入事例の手動操作。
  5. FAQの連続開閉、可変高、動きを抑える設定。
  6. フォームの必須入力、送信抑止、完了メッセージ、フォーカス移動。
  7. Tab移動とフォーカス表示。
  8. JavaScriptエラーと未解決アセットの有無。

制作確認用デモには noindex,nofollow を設定しています。
Basic認証のサーバー設定はサーバー側で管理し、閲覧案内用の共通認証情報のみ本記事に掲載しています。
フォームには、入力内容を送信せず資料も配布しないことを入力欄付近と完了メッセージの両方で明示しています。

デモ本体のcanonical、og:url、OGP画像URLは公開先の絶対URLへそろえます。
検索公開へ切り替える場合に限り、公開方針を確認して noindex を解除します。
