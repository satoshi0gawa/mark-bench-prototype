GITHUB PAGES

GitHub Pagesで静的サイトを公開する手順

GitHub Pagesを初めて使うときに迷わないよう、リポジトリの準備からローカル編集、GitHubへの反映、公開設定までをひとつの流れとして整理する。

01 / OVERVIEW

公開までの流れを確認する

GitHub Pagesは、リポジトリに置いたHTMLやCSSをWebサイトとして公開できる仕組みである。静的なプロフィールページや小規模な案内ページであれば、サーバーを別途契約せずに公開手順を試せる。

今回の作業は、リポジトリ作成、ローカルへの複製、ファイル編集、コミットとプッシュ、Pages設定という順番で進める。各段階で何を変更したかを確認してから次へ進むと、問題が起きた場所を切り分けやすくなる。

WORKFLOW

Repository → Clone → Edit → Commit → Push → Pages settings → Publish

02 / REPOSITORY

GitHubとリポジトリを準備する

GitHubへログインし、新しいリポジトリを作成する。ユーザーサイトとして公開する場合は、リポジトリ名をユーザー名.github.ioにする。別の名前で作成したリポジトリはプロジェクトサイトとして公開され、URLにリポジトリ名が含まれる。

  1. GitHubで新規リポジトリの作成画面を開く。
  2. 用途に合わせてリポジトリ名と公開範囲を決める。
  3. 作成後のリポジトリURLを控える。
PUBLIC CONTENT

GitHub Pagesで公開するファイルへ、APIキー、個人情報、公開できない画像や原稿を含めないようにする。

03 / LOCAL SETUP

ローカル編集環境を用意する

ファイル編集にはVS Codeなどのエディターを使用する。ターミナルでGitが実行できることを確認し、作成したリポジトリをローカルへクローンする。

git --version
git clone https://github.com/USERNAME/USERNAME.github.io.git
cd USERNAME.github.io

USERNAMEは自分のGitHubユーザー名へ置き換える。クローン後は、エディターでフォルダーを開き、編集対象が意図したリポジトリであることを確認する。

04 / EDIT

HTMLとCSSを編集する

公開元として選ぶフォルダーの直下に、入口となるindex.htmlを用意する。CSSや画像は役割ごとに分け、HTMLから相対パスで参照する。

公開用ファイルの役割と確認ポイント
ファイル役割確認ポイント
index.htmlページの構造と本文タイトル、見出し階層、CSSと画像の参照先
css/style.css色、文字、余白、レイアウトHTMLのクラス名と一致しているか
images/profile.jpgページ内で使用する画像ファイル名、容量、代替テキスト
LOCAL CHECK

プッシュする前にローカルサーバーで表示し、リンク切れとブラウザコンソールのエラーを確認する。

05 / PUSH

変更をGitHubへ反映する

変更内容を確認してからステージングし、作業内容が分かるメッセージでコミットする。最後にリモートリポジトリへプッシュする。

git status
git add .
git commit -m "Add initial website"
git push origin main

git statusは最初だけでなく、コミット前後にも実行すると、追加漏れや意図しないファイルの混入を見つけやすくなる。

06 / PUBLISH

GitHub Pagesで公開する

リポジトリのSettingsからPagesを開き、Build and deploymentのSourceでDeploy from a branchを選択する。公開元としてmainブランチと/(root)を選び、保存する。

  1. リポジトリのSettingsを開く。
  2. サイドバーのPagesを開く。
  3. SourceでDeploy from a branchを選ぶ。
  4. 公開ブランチとフォルダーを選択して保存する。
  5. 表示された公開URLへアクセスして確認する。

公開されない場合は、Pages設定、公開元ブランチ、index.htmlの配置、Actionsの実行結果を順に確認する。公開処理には少し時間がかかる場合がある。
