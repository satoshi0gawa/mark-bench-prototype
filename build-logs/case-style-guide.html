01 / PURPOSE

変換処理を整理した理由

Web制作では、同じ言葉をCSSクラス、JavaScriptの変数、ファイル名、CMSの管理項目などへ繰り返し入力します。用途ごとに求められる命名規則は異なり、手作業で大文字や区切り文字を直していると、表記揺れや入力ミスが起こりやすくなります。

Text Case Converterでは、ひとつの入力から複数の命名候補を同時に生成し、必要な形式をそのままコピーできる状態を目指しました。ここで重要なのは、出力時に大文字と小文字を切り替えることより、入力された文字列を正しく「単語」へ戻すことです。

PROCESS

入力文字列 → 単語境界を検出 → 共通の単語配列へ正規化 → 9種類のケースへ再構築

02 / NORMALIZE

入力を共通形式へ戻す

入力欄へ渡される文字列は、スペース区切りとは限りません。すでにcamelCaseやsnake_caseになっている場合もあれば、ハイフン、記号、連続した空白が混在している場合もあります。形式ごとに別の変換処理を用意すると、出力形式を追加するたびに同じ判定が増えてしまいます。

そこで、最初にハイフンとアンダースコアを区切りへ置き換え、不要な記号を除去し、空白で分割した単語配列へ統一します。文字の判定にはUnicodeプロパティを使用し、日本語を含む文字や数字を不用意に削除しないようにしました。大文字と小文字を持たない文字はそのまま保持され、区切り文字だけが出力形式に合わせて変化します。

03 / TOKENIZE

単語境界を判定する

camelCaseやPascalCaseには目に見える区切り文字がありません。そのため、小文字または数字の直後に大文字が続く位置へ区切りを追加します。さらに、XMLHttpRequestのように大文字が連続する入力では、頭字語と次の単語の境界も先に検出します。

const toWords = (value) => value
  .replace(/([A-Z]+)([A-Z][a-z])/g, '$1 $2')
  .replace(/([a-z0-9])([A-Z])/g, '$1 $2')
  .replace(/[_-]+/g, ' ')
  .replace(/[^\p{L}\p{N}\s]+/gu, ' ')
  .trim()
  .split(/\s+/)
  .filter(Boolean)
  .map((word) => word.toLocaleLowerCase());
DESIGN NOTE

変換結果の品質は、出力側の処理よりも単語をどこで分けるかによって決まります。すべての出力形式が同じ単語配列を参照することで、形式ごとの判定差も防げます。

04 / REBUILD

9種類のケースへ組み立てる

正規化した単語配列が用意できれば、あとは大文字・小文字と区切り文字の組み合わせです。Space系、ハイフン・アンダースコア系、識別子系の3グループへ整理し、同じ入力結果を比較できるようにしました。

INPUT        test text pattern

SPACE CASE   TEST TEXT PATTERN
space case   test text pattern
Space Case   Test Text Pattern
KEBAB-CASE   TEST-TEXT-PATTERN
kebab-case   test-text-pattern
SNAKE_CASE   TEST_TEXT_PATTERN
snake_case   test_text_pattern
PascalCase   TestTextPattern
camelCase    testTextPattern

Space Caseは各単語の先頭を大文字にする形式です。見出し候補や表示用ラベルとして使える一方、PascalCaseとは異なり単語間のスペースを保持します。

05 / VALIDATION

境界値と操作を検証する

通常の文章だけでなく、空入力、連続した区切り文字、先頭や末尾の記号、連続する大文字、日本語と英数字の混在も確認します。どの入力でも同じ正規化処理を通るため、変換形式ごとに結果が食い違っていないかを比較できます。

操作面では、入力に合わせた自動更新、空結果の「—」表示、結果がないときのコピーボタン無効化、コピー完了時の状態通知を確認しました。処理はブラウザ内で完結し、入力内容を外部サーバーへ送信しない構成です。

06 / RESULT

実装から得た判断

入力の解析と出力の組み立てを分離したことで、新しい変換形式を追加するときも共通の単語配列を利用できるようになりました。また、画面に表示するラベルと処理で使用するキーを分けたことで、表示順や名称を変更しても変換ロジックへ影響しにくい構成になっています。

一方で、頭字語を常に大文字で残すか、言語ごとのタイトル表記をどこまで扱うかは用途によって判断が変わります。Text Case Converterでは、結果を予測しやすい共通ルールを優先し、複数形式を並べて比較できることで選択を補助します。
